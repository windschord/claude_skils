## 基本原則

要求は**単調に増えるログではなく、常に無矛盾な現在の合意**である。したがって、

- 変更のたびに全体を検査する（差分だけを見ない）
- 消した要求も理由とともに残す（なぜ消えたかが後で最も効く情報になる）
- 矛盾は「後から直す」ではなく「入れさせない」

## 追加

### 追加前の必須確認

1. **同じことを言っている要求がないか**: `generated/index.md` を該当ドメインで検索する
2. **衝突しうる相手がいないか**: 追加しようとしている `measures.subject` / `asserts.key` を既存要求から検索する
3. **理由が言えるか**: `rationale.why` が書けないものは要求ではなく思いつき

### 手順

```bash
python3 scripts/reqctl.py next-id req              # 採番
# YAMLに追記
python3 scripts/reqctl.py validate --strict        # 検査
python3 scripts/reqctl.py generate                 # 生成物更新
```

新しいユーザーストーリーを追加した場合は、それを満たす要求を最低1件同時に追加する（`E-ORPHAN-US` になる）。

## 変更か置換かの判断

| 状況 | 扱い | 理由 |
|------|------|------|
| 誤字修正、表現の明確化 | 変更 | 合意内容が変わらない |
| 数値の調整（2秒 → 1.5秒） | 変更 | 同じ関心事の程度が変わっただけ |
| 検証手段の追加・差し替え | 変更 | 要求そのものは不変 |
| 対象範囲の拡大・縮小 | **置換** | 満たすべき条件が別物になる |
| 前提となる方針の転換（30日保持 → 24時間失効） | **置換** | 過去の合意を無効化した事実を残す必要がある |
| 要求の分割（1件 → 3件） | **置換** | 旧IDを `superseded` にし、新3件が `supersedes` する |

**迷ったら置換**を選ぶ。置換はIDが増えるだけで情報を失わないが、変更は履歴を上書きする。

## 変更

```text
1. impact <ID> を実行し、被依存要求・ストーリー・テストを把握する
2. 変更提案レポートを作成する（assets/templates/change_proposal_template_ja.md）
3. ★ ユーザー承認 ★
4. YAMLを更新する。理由が変わったなら rationale.why も更新する
   - 変更が既存の decided_at を無効にするなら decided_at も更新する
5. validate --strict でエラー・警告をゼロにする
6. verification が指すテストの更新要否を判断し、必要なら実装側の変更をタスク化する
7. generate → 差分をユーザーに提示
```

数値を変えたときは、**同一 `subject` を持つ他の要求を必ず読み直す**。区間が空にならなくても、実質的に無意味な余地しか残らない場合がある（例: 上限2秒・下限1.9秒）。

## 廃止・置換

### 単純廃止（後継なし）

```yaml
- id: REQ-0007
  status: deprecated
  rationale:
    why: （元の理由はそのまま残す）
    retired_why: 対象機能の提供終了を2026-08-20に決定したため
```

依存していた要求（`E-DEAD-REF`）をすべて処理してから廃止する。

### 置換（後継あり）

```yaml
- id: REQ-0003
  status: superseded
  rationale:
    retired_why: 監査指摘により長期セッションが不可となり REQ-0004 に置き換えたため

- id: REQ-0004
  status: active
  supersedes: [REQ-0003]
```

置換は必ず**新旧を同じコミットで**行う。片方だけ入ると `E-SUPERSEDE` になる。

### 物理削除してよい唯一のケース

同一ブランチ内で、まだ一度もマージされていない要求を取り消す場合のみ。既定ブランチに入った要求は必ず墓標として残す。

## 承認ゲート

| 操作 | 承認 | 提示するもの |
|------|------|-------------|
| 要求の追加 | 不要（差分提示のみ） | 追加した要求と検査結果 |
| 要求文・数値の変更 | **必須** | 変更提案レポート＋`impact` 出力 |
| 廃止・置換 | **必須** | 変更提案レポート＋依存元の処理方針 |
| 衝突の許容（`conflicts_with`） | **必須** | 双方の要求文と `tradeoff` 案 |
| 優先度の変更 | **必須** | 変更理由 |
| 警告の解消（表現修正のみ） | 不要 | 差分 |

承認を得ずに変更してはならない。承認待ちの間に他の作業を進めてよいが、YAMLは書き換えない。

## レジストリの分割

1ファイルが300行を超えたらドメイン単位で分割する。分割は要求の内容を変えないため、`validate` の結果が分割前後で一致することを確認する。

```bash
python3 scripts/reqctl.py validate --json > /tmp/before.json
# 分割作業
python3 scripts/reqctl.py validate --json > /tmp/after.json
diff /tmp/before.json /tmp/after.json   # findings に差分がないこと
```
