## 使える手段

| 手段 | 内容 | 向いている場面 |
|------|------|---------------|
| Agent tool の `model` パラメータ | サブエージェントを `sonnet` / `opus` / `haiku` / `fable` で起動する。エージェント定義の `model:` より優先される | 通常の委譲（既定） |
| エージェント定義の `model:` | `.claude/agents/*.md`（プラグイン配布なら `agents/`）のfrontmatterで既定値を決める（例: `agents/task-executing.md` は `model: sonnet`）。Agent toolの`model`指定で上書きできる | 同じ役割を繰り返し使う場合 |
| `/model`（ユーザー操作） | メインセッションのモデルを切り替える | 作業全体を別モデルで進めたいとき。スキルからは実行できない |

## 手順

1. 現在のメインセッションのモデルを把握する（システム情報で確認。分からなければ推奨モデルとの比較を省略し、委譲する）
2. 作業ごとの推奨モデルと現在のモデルを比べ、`SKILL.md` の原則6に従って実行者を決める
   - 推奨モデルが現在のモデルと同じ → 自分で実行する
   - 推奨モデルが現在のモデルと異なる（上位でも下位でも）→ 推奨モデルを指定して Agent tool を起動し、委譲する
   - 1〜2ステップの軽微な作業 → 自分で実行してよい（原則6の例外）
3. 委譲時は `model` を明示する（省略時はエージェント定義の `model:`、定義がなければ呼び出し元のモデルになる。意図したモデルで動く保証がなくなるため、明示する）
4. サブエージェントの結果を受け取り、レビュー対象なら1つ上のモデルの Agent tool へレビューを依頼する。レビュー担当が指定したモデルで実行されたかを、実行状況の表示や結果で確認する。組織の設定などで指定どおりに実行されなかった場合は、そのモデルによるレビューとして扱わない。Fableが使えなかったときは、Opusの別コンテキストで代替レビューを行い、その旨をユーザーに報告する
5. 並列にできる独立した作業は、同じ応答内で複数の Agent tool を呼ぶ

## 指示書の書き方

サブエージェントは会話を知らない。次の項目を埋める。

```text
## 目的
（何のための作業か。元のユーザー依頼を要約）

## 入力
（対象ファイル・Issue番号・関連する決定事項。パスは具体的に）

## 制約
（触ってよい範囲、守る規約、禁止事項）

## 完了条件
（何がそろえば完了か。テスト・検証コマンドを含める）

## 出力形式
（報告に含める項目。レビュー依頼ならレビュー観点と指摘フォーマット）
```

## モデル固定のエージェント定義（任意）

同じ役割を何度も使う場合は、`.claude/agents/`（プラグインとして配布する場合は `agents/`）に定義を置くと、既定のモデルを決められる（Agent toolの`model`指定で上書き可）。

```markdown
---
name: reviewer-opus
description: Sonnetの成果物をレビューする。差分と要求を受け取り、指摘を返す
tools: Read, Grep, Glob
model: opus
---
（レビュー観点と出力形式を記述）
```

作成するかはユーザーの判断に委ねる。このスキルは定義の追加を必須にしない。

## 委譲できない場合

Agent tool が使えない、またはモデルを指定できない場合は、推奨モデルと理由を1〜2行で伝え、ユーザーに `/model` での切り替えを依頼する。切り替え後は、その旨を確認してから作業を再開する。レビューが必要な作業は、実行モデルを切り替えたうえで依頼する。
