## 使える手段

利用できる手段は環境ごとに異なり、Coworkで各ツールが使えるかは環境しだいである。**ツール一覧で存在を確認し、使えるものだけを選ぶ**（存在しない手段を前提にしない）。Claude Codeのクラウド／リモートセッションでは、セッション作成ツールを使える場合がある。

| 優先 | 手段 | 内容 |
|------|------|------|
| 1 | Agent tool の `model` パラメータ | サブエージェントを `sonnet` / `opus` / `haiku` / `fable` で起動する（Claude Codeと同じ） |
| 2 | セッション作成ツール（例: `create_session`） | `model` にモデルIDを指定して別セッションを起動し、メッセージで作業を渡す。結果は対象セッションのイベント／メッセージで確認する |
| 3 | ユーザーによるモデル切り替え | 手段1・2がない場合、推奨モデルを伝えて、UIのモデル選択で切り替えてもらう |

## 手段の選び方

| 状況 | 選ぶ手段 |
|------|---------|
| 短時間で完結する分析・レビュー・実装 | 1（Agent tool） |
| 長時間・並列・独立した作業で、会話から切り離したい | 2（別セッション） |
| どちらも使えない | 3（ユーザーに切り替えを依頼） |

## 手順

1. 利用可能なツールを確認する（Agent tool、セッション作成ツールの有無）
2. 作業ごとの推奨モデルと手段を決める（`references/routing_criteria_ja.md`）
3. 手段2を使う場合
   - 環境を指定しなければ呼び出し元の環境が継承される。別環境が必要なときだけ環境IDを明示する（IDは環境一覧から取得し、推測しない）
   - `model` には現行のモデルIDを指定する。IDが分からない場合は推測せず、ユーザーに確認するか、手段1か3に切り替える（システム情報に載っているのは通常、現セッションのモデルIDだけ）
   - 作業の指示書（`references/adapter_claude_code_ja.md` の「指示書の書き方」と同じ項目）は、`prompt` 引数または最初のメッセージで渡す
   - 起動後、セッション情報（`get_session` の `configured_model` / `last_served_model`）で実際のモデルを確認し、フォールバックしていないかを検知する
   - 完了は自動では通知されない場合があるため、セッションの状態とイベントで結果を確認する
4. 成果物のレビューは、作成者の1つ上のモデルで同じ手段を使って依頼する。Fableの成果物は、新しいセッション／サブエージェント（別コンテキスト）のFableへ依頼する
5. 起動したセッションの結果を統合し、ユーザーに報告する。不要になった子セッションは、ユーザーの意向に従って片づける（勝手にアーカイブしない）

## モデル指定の注意

- 子セッションは、モデルを省略すると呼び出し元のモデルになる。**必ず明示する**
- Cowork環境のセッションは、読み込む引数が限られるため、モデル指定を無視する場合がある。反映の有無は上記のとおり確認する
- 作業を渡すセッションには、機密情報（認証情報など）を指示書へ書かない
- 起動した別セッションの変更（コミット・PR）は、親セッションの作業と衝突しないよう、対象ブランチ・ファイルを指示書で分ける

## 委譲できない場合

手段1・2が使えないときは、次の形でユーザーに依頼する。

```text
[model-routing] この作業は {モデル名} が適しています（理由: {1行}）。
現在のモデルから切り替えて、続きの依頼を送ってください。
```

切り替え後に再開する場合は、ここまでの判定結果と未完了の作業を短く再掲して作業を続ける。
